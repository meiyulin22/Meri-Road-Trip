# Meri Generate Plan 实施交接

2026-11-11 · 设计和待办。真实按钮已交接旅程快照和偏好到计划页。第一轮调研已可通过脚本运行，具体日程待生成。`/plan-preview` 使用独立的示例数据。流程顺序和首版范围以本文为准，其他产品决定见 [Planner 规划笔记](README.md)。

## 生成流程

1. **读取 TripState 快照。** 已选省、市和景点决定规划范围。Workspace 跨省合计最多新增至 10 个城市／自治州，空省和景点不占城市名额。聊天只用于提取偏好。新增候选属于本次计划，用户已删除的地点不能从历史对话恢复为已选地点。
2. **按城市做第一轮调研。** Research Agent 使用 Kimi `search_pro` 找一小批候选。已确认天数时覆盖最多 10 个已选城市，每批并行两城，每城最多两次查询。有点名景点时一次查点名、一次查城市候选。只有城市时先查候选，再由 Agent 决定是否补查。查不到的点名景点仍保留，并标明未知。
3. **先分天。** 多城市且总天数已确认时，Plan Agent 看各城候选摘要、用户约束和已知转场时间，提出城市顺序、各天所在城市和停留晚数。代码核对天数、已选城市和用户确认的顺序。单城市由代码直接分天。没有确认总天数时，只调研第一个已选城市、生成示范第一天；总天数留空，「剩下的几天」等用户输入或确认后再解锁。
4. **按天筛选和排程。** 代码按所在城市、开放窗口和已知限制筛候选。周一闭馆只排除周一。普通降雨等体验因素可以交给 Jev，按当天条件和用户偏好为可选景点打分。用户指定的景点保留，排不进去就显示冲突。由同一个 Plan Agent 填充每天的景点和建议时间。工作流在两个阶段之间传递结构化数据，分天和日程分别校验。日期未知时用相对天序，天气和日期相关的开放状态标为待核实。
5. **精查草稿。** 核实拟排景点和少量备选在拟定日期的开放、预约和临时通知。首版由代码检查已知冲突，同一个 Plan Agent 指出需要补查的城市、日期和原因。Research 补足证据后，Plan Agent 只改受影响的日期。独立审核 Agent 留待对照测试。
6. **校验路线和结果。** 代码根据选点安排路线顺序，使用路线工具的结果核对车程、转场和开放窗口。缺少车程就标未知。检查候选范围、跨天重复和用户指定景点的覆盖。排不下时只重排受影响的天，预算耗尽则交付能用的部分并显示原因。

## 计划页对话分流（设计）

生成真实行程后，计划页底部的修改对话框可用 Jev Choice 判断消息是询问已有计划、调整现有行程、需要补查资料，还是需要澄清。问答交给 Kimi 读取计划和已有证据。修改由代码校验范围后调用 Plan Agent，缺事实才触发定向 Research。置信度低时先澄清或交给 Kimi 理解。首版对照中文样例测试分流效果。

## 数据交接

| 数据 | 最小内容 |
| --- | --- |
| 景点卡 `SpotCard` | 景点 ID、城市、名称、用户是否点名、开放与预约、室内外与步行强度、建议停留时间。事实附来源和查询时间，未知字段显式表示。 |
| 计划草稿 `PlanDraft` | 日期或相对天序、城市、景点 ID、建议时段、路线或车程、冲突和未知项。模型以景点 ID 引用候选，代码补入路线和核验结果。 |

## 实施顺序

- [x] **接通 Workspace 交接。** 点击后服务端读取保存的状态和用户原话，交给真实计划页。同一标签页刷新复用快照。
- [x] **接通第一轮调研。** 验证脚本读取 PlanHandoff JSON，通过 Kimi 搜索按城市产出带原文出处的景点卡。只有省份时报告待确定的省范围。按钮仍只执行交接。
- [ ] **验证规划核心。** 用测试景点卡跑单城市示范第一天，再跑多城市分天、每日排程和校验。核心放在 `src/agents/planner/`，外部接口放在 `src/platform/`。城市、天数和候选都通过参数传入。先用脚本和测试跑通，再把日程接到页面。
- [ ] **接第二轮精查。** 基于拟定日期核实草稿和备选。比较候选覆盖、行程可行性、搜索次数、耗时和 token。先建立 Plan Agent 选点基线，再对照 Jev 的中文评分效果。
- [ ] **分批接提供方和产品入口。** 天地图地点核验、路线和浏览器地图留到对应阶段，在能访问天地图的机器上实测，用脱敏结果验证适配器。再按需要接天气、机票、酒店、高铁和审核 Agent。接入真实生成时确定运行接口、计划存储、进度及失败恢复。

## 第一轮验收

| 输入 | 应看到的结果 |
| --- | --- |
| 只选一个城市，未确认天数 | 示范第一天可生成，后续日程锁住。 |
| 丽江、大理共五天，提供测试转场时间 | 覆盖两座城市，总天数对得上，转场计入时间，无跨天重复景点。城市如何分天由输入决定。 |
| 用户点名的景点当天闭馆 | 能换日就换日，排不进去就说明冲突。其余可用结果照常返回。 |

待定事项包括只有省份时是否要求先选城市（当前建议）、首批候选的发现查询，以及真实供应商的返回质量和预算上限。
