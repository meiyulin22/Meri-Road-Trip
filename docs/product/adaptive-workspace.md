# Meri Adaptive Workspace：设计方向

> 2026-10-01 精简。本文件保留未来界面方向，不描述当前已实现能力，也不授权本轮开发。当前实现见 [ARCHITECTURE.md](../ARCHITECTURE.md) 和 [USER_FLOW_CURRENT.md](../USER_FLOW_CURRENT.md)。

## 想解决什么

Journey 始终是中心。未来 Workspace 可以随着用户正在做的决定，调整相关信息的展示重点：问“明天能不能徒步”时突出天气与风险，问“怎么过去”时突出交通与路线。改变展示不改变已保存的旅程决定。

## 给 AI 的边界

- 根据当前 TripState 和实际取得的信息展示；没有研究数据时不能假装有天气、风险或路线结论。
- 使用应用预写、可校验的组件和数据，不让模型生成任意 React/CSS 或可执行界面。
- 实现方式由后续真实需求决定，不预先承诺决策引擎、World State 大模型、框架或组件注册系统。
- Companion 若表达思考、完成或提醒，应对应真实状态；这不是提前实现研究能力的要求。

当前已有固定 Workspace、持久化聊天、目的地选择和准备度检查，没有自适应布局或研究引擎。涉及未来界面设计时再参考本文，普通 bug 修复无需展开这些设想。
