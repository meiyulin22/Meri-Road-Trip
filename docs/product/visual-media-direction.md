## 图像与视频探索方案

### 1. 会呼吸的首页山景：优先试验

以现有首页山景为参考，先生成一张构图完整的关键画面，保留上半部的浅色留白供标题与输入框使用。再用同一关键画面制作约 6–10 秒的短循环：云缓慢移动、湖面轻微波纹、树梢小幅摇动，镜头固定，首尾接近。

动态集中在页面底部，文字和输入区域保持稳定。静态图先显示，视频就绪后柔和切换；静音、无音轨，减少动态效果时显示静态图，页面不可见时暂停。视频是否自动播放以及手机是否只显示静态图，需要在试验中验证。

先做一个场景验证风格、循环接缝和加载开销，再考虑更多场景。

### 2. 小熊的营地：角色连续性优先

用现有小熊作为参考，生成角色设定板，固定脸型、服装、背包、比例与调色板；再制作看地图、泡茶、整理背包、望向远山等动作关键帧。

网站已有精灵图播放器，可保留为日常模式和回退方案。新增探索包括立体小熊和互动营地：助手提供角色参考图，用户使用外部 3D 工具制作资产，再评估是否适合接入网站。模型生成与可用动作是不同阶段，不能假设图片转 3D 后就具有完整绑定和动画。长视频适合展示故事，精灵图或有绑定的 3D 角色适合及时响应对话状态。

参考图灵感：同一角色的正面、侧面、背面图，简洁背景、清楚轮廓，背包和地图等道具可考虑独立制作。此处只定义候选素材，不要求本轮生成。

已有小熊行为已实现，本文建议的是新增素材探索，不能描述为新增动作已可用。

### 3. 旅程插画封面：让每段旅程可识别

生成一组统一风格的主题封面，例如山地、海岸、森林、湖泊、古镇、露营，优先用于目的地尚未明确的探索状态或用户显式选择的氛围主题，不必为每条消息在线生成。明确地点已有高德照片，不默认换成生成图片。

可与现有真实地点照片并存。插画属于氛围装饰；不能被呈现为当地实景或路线、天气、可达性的证据。未知目的地使用中性封面，不从旧聊天恢复已删除地点。

### 4. 工作区的营地小窗：聚焦而轻量

在小熊附近尝试一块小型动态场景：远山、帐篷、营地桌、轻微升起的蒸汽。工作区的主要任务仍是读对话和编辑状态，动态场景不抢占文字区域，也不扩大为持续运动的全屏背景。

### 5. 旅程邀请短片：后续可选方向

将几张插画、当前旅程名称与日期组合成约 10–15 秒的分享短片。文字通过代码或视频编辑准确叠加，避免让生成模型直接画汉字。优先作为用户主动播放或导出的内容。

当前没有生成计划，短片只能表达旅行想法、已选择目的地与氛围，不能包装成已验证的行程预告。

已认可的是分享产物这个方向，而不只限于短片。候选分享页可以包含旅程名称、已保存目的地、日期、真实照片和装饰插画；PDF对应同一组内容的静态展示。默认不包含完整私人聊天。是否分享由用户主动操作，公开内容范围、只读访问与撤回方式在未来实施前讨论。链接不可直接复用当前依赖访客归属的工作区地址。

本节保存远期灵感。分享链接与 PDF 明确在 Generate Plan 实现后再做，当前只讨论页面与视觉体验。

## Web3D 灵感池

- 拖动营地底座，从不同角度查看小熊、帐篷和地图桌，限制镜头范围以保持构图。
- 对话处理中，小熊看地图；保存目的地后，小熊放一面小旗。后者只反映真实保存结果，不反映尚未选择的建议。
- 点击背包查看一组装饰道具；不将尚未实现的装备检查包装成可用功能。
- 通过点击台灯体验营地昼夜美术切换；明确属于主题切换，不暗示实时天气。
- 从营地的小地图或相片架进入现有目的地照片展示，把角色世界与旅程内容连接起来。
- 面试演示采用“打开营地 → 拖动查看 → 触发一次角色反馈”的短交互链，展示素材制作、场景组织与产品状态结合。

上述均为灵感，未确定采用。首轮优先一个主角、少量道具和少数清楚的交互，避免范围扩张到完整游戏。

## 素材制作原则

- 先静态关键画面，后视频；先统一风格，再批量扩展。
- 使用现有素材作为参考，保持水彩环境与像素角色的分工。
- 生成媒体负责景物与角色，界面文字、表单、日期和按钮由应用渲染。
- 背景场景保持固定镜头，避免大幅推进、晃动和频繁切镜。
- 为每段视频保留静态 poster；小尺寸预览、无音轨、按需加载，实测体积和流畅度后再接入。
- 日出、雨天、秋色等可以作为美术主题，不代表真实时间或实时天气；不擅自接入未实现的天气能力。
- 尚未选定视频生成提供方。本轮仅保存方向，不声称已经具备视频生成工具或已经制作素材。

1. **纸上营地**：营地从一张折叠旅行地图展开，而不是把另一张山水背景塞进卡片。纸面、帐篷、角色和原线框半球组成一个小世界；地图是装饰，不暗示真实路线。
2. **同一位旅行伙伴**：首页与工作区复用同一角色资产。未来可尝试导航完成后，小熊展开地图的短过渡；不能用动画假装后台操作已经成功，也不延迟正常进入工作区。
3. **把真实照片带入营地**：用户保存目的地成功后，在小相片架上出现对应高德照片；移除地点后同步移除。未选推荐不成为营地纪念品。点击照片关联现有地点展示，具体交互待设计。
4. **灯光作为可玩细节**：点击灯笼切换营地的日夜美术主题。灯光和材质变化足以体现实时 3D，不需要新增天气系统。
5. **未知目的地也有设计**：未确定目的地时，地图保持折叠或留白；有已保存选择后再摆出照片。避免编造路线、地理位置或“规划完成百分比”。
6. **少而连贯的动效**：首页可探索底部景观短循环；Workspace 优先局部角色反馈。两者分别试验，避免视频、照片环、角色持续运动互相争夺注意力。

## Web3D 制作与接入流程（Generate Plan 完成后再考虑，未实施）

以下流程作为后续参考保存。当前不启动建模、骨骼动画或 Three.js 接入；先完成真正的 Generate Plan，再按当时需要缩小 3D 范围。

建议以 **Three.js 为底层、React Three Fiber 为 React 场景层、Drei 为常用辅助工具**。现有项目使用 React；R3F 是 Three.js 的 React renderer，不是另一个建模工具。当前项目没有接入这些依赖，本轮不安装。参见 [R3F 官方介绍](https://r3f.docs.pmnd.rs/getting-started/introduction)。

| 阶段 | 工作与产物 | 通过条件 |
| --- | --- | --- |
| 1. 确定角色 | 助手先生成同一角色的正、侧、背参考图，姿态自然展开、光照中性、背景简单；帐篷、桌子、地图等单独制作参考 | 三视图身份一致，四肢不被桌子遮住；不把整张 UI 截图送去生成一个混合模型 |
| 2. 图片转模型 | 用户在混元 3D 或选定平台先试一个小熊，导出可检查的 GLB 与贴图 | 能检查背面、手脚、背包和薄片；先判断单个角色是否可用，再批量生成道具 |
| 3. 整理资产 | 在 Blender 检查尺度、原点、法线、穿插和贴图；必要时减面或重拓扑，道具分离 | 输出干净、尺寸合理、可独立摆放的模型；初始预算可试角色 1–3 万三角面、全场景 5–10 万面、主要贴图 1K，均需实测调整 |
| 4. 第一版实时场景 | 加正交相机、柔和灯光、接触阴影，支持有限旋转、悬停和开关灯 | 先形成可展示的小场景；这些反馈可以不依赖骨骼动画 |
| 5. 角色动作 | 需要挥手、低头看地图时，再完成骨骼绑定、权重和少量动画片段 | 优先 idle、看地图、确认反馈三类；逐个检查变形与道具穿模。生成模型不等于自动具有可用动作 |
| 6. 嵌入页面 | 独立的客户端 3D 区域加载 GLB，原有聊天、表单和文字保持 DOM；先保留现有 SVG 半球 | 不遮挡输入、不造成滚动/拖拽冲突，复用已有 companion 行为与真实状态；不另建一套旅程状态 |
| 7. 性能与回退 | 按需加载、限制像素比、离屏暂停；静止场景尝试按需渲染，连续动作只在需要时运行 | 检查移动端、低性能设备、减少动态效果偏好及 WebGL 不可用时的静态回退；加载和帧率以实测为准 |

GLB 是建模工具到网页的交付格式之一，不是生成步骤。Three.js 可以播放导入模型的骨骼/形变动画，但不能凭静态模型自动创造高质量动作。参见 [Three.js 动画系统](https://threejs.org/manual/pages/animation-system.html)、[R3F 模型加载](https://r3f.docs.pmnd.rs/tutorials/loading-models)和[性能指南](https://r3f.docs.pmnd.rs/advanced/scaling-performance)。

腾讯官方示例包含图片生成模型任务和 GLB 输出，见[混元 3D 快速入门](https://cloud.tencent.com/document/product/1804/120757)。用户所称“彼得 3D”尚未确认具体产品；如果指 Tripo，其[官方工作室教程](https://www.tripo3d.ai/blog/tripo-studio-tutorial-english)介绍了自动绑定、动画和 GLB/FBX 导出，但实际生成质量、可用额度和当前账号能力需要在制作时确认。

建议先离线制作并审核资产，网站部署静态模型文件；不在这一阶段新增运行时图片转 3D 服务。第一轮验收目标是“一只风格匹配的小熊＋小营地＋可旋转与灯光反馈”，第二轮再接动作和真实旅程反馈。首页全屏 Web3D、复杂角色剧情与分享产物均不因此提前进入实施范围。
