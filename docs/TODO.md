## 已决定的（不要重复讨论）

- **T4a 已实现（2026-10-23）**：`q1` 关键词搜一次；如果页首不是"整个景区"级别的东西（典型是 稻城亚丁 只返回机场/酒店/景区管理局），就拿页面前两条结果的**区县名**做 `q13` 分类搜索，`dataTypes` 分别取 `风景名胜` 和 `山`（`dataTypes` 一次只认一个值，逗号分隔实测返回 0 条）。行政区答案也补，但把行政区自己排最前；**省级答案不补**。
  实测：稻城亚丁 → `甘孜州稻城亚丁景区` 第一（2593ms）；黄山 → 黄山市 第一 + `黄山风景区` 第二（966ms）；丽江 → 丽江市 第一 + `丽江古城` 第二（1264ms）；玉龙雪山 走快路只要 261ms；云南 274ms。
  仍然不行：**九寨沟**（页首就是江苏泰州兴化的同名景点，快路不补）、**苍山**（全国页里没有云南，区县候选是宾阳/仁寿）→ 这两条要 T4b 的先验。
- **知名度信号：天地图没有**（2026-10-23 向官方客服 AI 核实 + 本人实测）：
  - 没有景点等级字段（5A/4A/国家级/省级），`show=2` 的详细字段里只有 typeCode、省市县和电话。
  - 没有排序参数（没有 `orderBy` / `sort`），`q13` 的返回顺序是入库顺序，文档未说明——所以稻城县第一条是景区，大理州前 300 条没有苍山。
  - 没有父子字段（没有 `parentId`），子景点只能靠 `address` 字符串聚类。
  - **`ename`（英文名）不能当信号**：实测大理市 山 212 条、稻城县 风景名胜 40 条、黄山区 风景名胜 290 条，`ename` 全为空。
  - 结论：想去掉 Wikidata 之后恢复"哪个同名景点更有名"，只能靠 T4b（地理先验）和 T5（别名表），没有别的免费信号。
- **`dataTypes` 多值彻底不支持**（2026-10-23 实测）：`风景名胜,公园`、`180400,180304`、`风景名胜,山`、`180400,260203` 四种写法**全部返回 0 条**，而每个单值都正常（590 / 212 条）。文档写的"多个分类用逗号隔开"在这个接口上不成立，所以每个类别必须单独发一次请求。
- **`q13` 的 `mapBound` 是必填但不过滤**（2026-10-23 实测）：大理市 风景名胜 传全国框、市区框、古城极小框，总数都是 **590**；玉龙县传全国框和县城框都是 **605**。所以「用 `mapBound` 把范围缩到路线包围盒」这个做法**不成立**（客服 AI 的说法与实测相矛盾），"自驾路线沿线景点"需要另外设计。
- **分类搜索的边界**：`start` 上限 300（实测 `start=600` 直接 HTTP 400），单次最多 600 条，而且 `mapBound` 不给缩范围的手段。县级单位通常够（大理市 590、玉龙县 605 已贴边）；**单类别超过 600 条的县目前没有官方取全办法**，除非确认支持乡镇级 `specify`（待问）。**不能当全国索引**。
- **照片**：先不做。天地图没有照片，国内来源未定。换来源时只改
  `src/platform/place-photos/no-place-photo-provider.ts`。
- **全国景点 RAG / 预建索引**：不做。批量导出全国景点坐标与项目已记录的坐标合规规则 ③ 冲突；要补召回就做 T5 的别名表。
- **LLM 排序**：不做。天地图没有候选可排时它只能猜，而且多 2–4 秒。
