# Meri 动效原型交接包

这个目录用于交给另一台机器上的 Claude 制作可预览的动效。现在只有需求、素材副本和演示数据，还没有动画实现；不会接入 Meri 正式页面。

## 给 Claude 的任务（可以直接复制）

请在这个独立目录中制作 Meri 的三个可运行前端动效原型：

1. 打开首页：像进入山间营地。先有静态山景，再让山层、品牌、标题和输入框自然入场，小熊有轻微回应。保持现有首页围绕输入框的布局；主要入场约一秒是初始建议，可以根据效果调整。输入框出现即可操作，动画不阻挡输入。
2. 点击 Generate plan：小熊沿抽象的像素山路前进，营地代表规划任务阶段。根据外部传入的步骤状态更新营地与文字，最后从生成场景过渡到示例计划。山路是进度插画，不需要真实地图。
3. 聊天框趴熊：点击首页输入框，小熊从框后探头、抓住上沿，趴在上沿偏右的位置。身体和两只爪子保持搭住边框，眼睛与头部随鼠标在四周移动而自然转向，幅度有限、平滑跟随；不让整只熊机械旋转。鼠标离开输入框区域后约 0.3 秒再缩回，避免边缘反复触发。先做独立演示，保留原有输入、发送和键盘操作，不遮挡文字或拦截点击。

视觉沿用随包提供的 Meri 山景、山形品牌图和小熊，使用暖米色、森林绿、少量赤陶橙，保留像素质感。首页和规划过渡像发生在同一个世界。允许探索节奏、镜头与场景层次；这次不重做产品布局、不做 3D。

使用独立的 React 演示工程，优先 React + Motion（`motion/react`）+ CSS Modules，便于以后接回现有项目。依赖和 lockfile 都放在本目录，提供明确的安装、启动、构建命令。依赖安装完成后，预览不应需要联网加载字体、脚本或图片。

请只在原型目录内工作，不改 Meri 主项目的 `src/`、`public/`、依赖、配置或文档。不要读取主项目环境变量，不接数据库、模型、Mastra、天地图、高德或其他真实 API，也不需要修复这些服务的连通性。原型的输入和按钮只在本地演示，不创建 Journey。

## 演示状态与以后接 Mastra 的边界

- `demo-scenarios.json` 是视觉演示格式，不是 Mastra 原生 JSON，也不是已经定稿的后端协议。阶段名称、数量和时长均为示例。`atMs` 只给演示播放器使用。
- 把演示播放器与视觉组件分开：播放器负责按样例发送更新；动画组件接收当前阶段、任务状态和描述。以后由 Meri 的适配代码把 Mastra 实时事件转成组件输入。
- 营地对应用户能理解的任务阶段；Agent 的模型轮次和工具调用可显示为当前营地的细节。阶段通过 ID 识别，支持传入不同数量的阶段，不依赖固定五站或工具调用次数计算百分比。
- 并行任务分别显示状态；一个任务完成不能将其他任务一起标为完成。重试保留同一任务身份和其他已完成的进度，小熊留在所属营地即可。
- 只有明确成功才点亮成功标记。Mastra 的 `workflow-step-finish` 本身不证明成功；以后由服务端结合步骤结果状态、工具结果作判断。
- 最终展开计划由单独的 `run: ready` 演示记录触发，对应未来代码校验并保存成功。存在未知项的结果要保留未知提示。样例文字和地点只用于预览，不表示真实研究结果。
- `completed_with_unknowns` 使用保留未知标记的完成态，不画成所有信息均已核实的成功状态。
- 等待确认时暂停推进，允许继续演示；失败时保留已完成阶段。组件不自行猜测后端完成、重试或恢复。
- 总工作量未确定时显示当前阶段和任务状态；不要按时间增长百分比。示例计划页只承接动画收尾，不扩展成完整 Planner 产品。

目前 Meri 的 Generate plan 仍然只检查准备度；Planner、计划存储和网页实时进度尚未接通。本包只用于先看动效，正式集成以后再做。

## 预览与交付

请提供首页入场、规划过渡、聊天框趴熊三个可分别重播的预览场景，以及独立的演示控制区：重播、逐步推进、自动播放、暂停、切换场景、等待后继续。演示控制区与产品画面分开，方便以后移除。

至少检查桌面和约 390px 手机宽度；支持系统减少动态效果，改用静态场景和步骤文字；页面隐藏时暂停装饰动画。计划提前就绪时可以尽快进入结果，不必等待预设演出播完。

交回完整源码、独立依赖与 lockfile、新增素材、启动命令、桌面/手机截图或录屏，以及实际执行的检查结果。标注临时素材。根目录与本目录以外的生产文件不在交付修改范围内。
